### Свежий лог и причина 400 — Codex, 2026-10-28

- Прочитан актуальный `/mnt/mmc/MUOS/application/tgmuos/log.txt` через SSH-алиас `anbernic`. Приложение отрисовало первый кадр, затем `setTdlibParameters` получил `400: Valid api_id must be provided`; последующий `getProxies` получил `500: Request aborted`. Процесса `tgmuos` сейчас нет.
- Приватный конфиг читается, режим `0600`; только булевы признаки проверены: api_id положительный, api_hash — 32 hex-символа. Содержимое не печаталось. Ошибка возникает после загрузки credentials.
- Сверка запроса с официальным примером TDLib из установленного commit `ea3f69ce…`: текущая JSON-схема задаёт поля `setTdlibParameters` на верхнем уровне. Код отправлял их как legacy-вложенный `parameters`, отчего новая библиотека видела нулевой api_id. Исправление: плоская форма первой; для старых библиотек один fallback на вложенную после точного `Parameters aren't specified`.
- Интеграция двух новых источников подписки идёт в приватный `subscription-sources.txt`; ручной TLS outbound останется отдельным selectable default вместе с DNS и direct-bypass правилами. URL в журнал не копировать.

### Движок прокси — Codex

Пользователь спросил про Xray-core как дополнительный движок. Xray официально документирует VLESS `xtls-rprx-vision` и REALITY и публикует Linux ARM64 сборки. Это хороший кандидат для отдельного A/B на тех Reality-нодах, где sing-box отказал: оба движка могут отдавать тот же локальный SOCKS5 TDLib. Пока оцениваю вариант; параллельно не меняю текущий рабочий sing-box TLS-профиль.
